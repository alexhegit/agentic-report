# GitHub 周度工作总结（2026-11-06 08:31—2026-11-13 08:31，CST）

## 本周概览

本周重点是 AMD/NVIDIA 平台上的生成式推理优化，以及 VLA 推理性能继续收敛。h3-hip 完成 R9700、ComfyUI 和服务化发布，并通过新 SDPA、VAE 内核及磁盘缓存进一步提速；EdenLive 则完成 MI300X 双向生成、编译优化和流式解码验证。rocPAI-Forge 的 vla-hip 连续发布多个版本，在保持门控或闭环精度的前提下，分别压缩 pi0.5、GR00T N1.7 和 VLA-JEPA 延迟。

## alexhegit

### 1. h3-hip 完成 R9700/ComfyUI 发布，并继续推进逐位一致的内核优化

- 发布 [v0.19.0](https://github.com/alexhegit/h3-hip.c/releases/tag/v0.19.0)，正式纳入 Radeon AI PRO R9700、ComfyUI V3 节点和增强后的 `--serve`：支持缓存释放、FastH3 服务端适配器、并发请求、SSE、及时取消以及跨任务状态隔离。gfx1201 上 `serve-regression` 58 项通过，连续六类任务均与 CLI 输出一致。
- 随后发布 [v0.20.0](https://github.com/alexhegit/h3-hip.c/releases/tag/v0.20.0)：gfx12 Sᵀ/Oᵀ SDPA 约快 **26%**，VAE linear 约快 **25%**，重复提示的磁盘缓存将 fox-s2 从 **35.9 秒降至 12.9 秒**。完整 R9700 矩阵的 39 个视频 MD5 全部不变，dense 路径端到端提升 **11%–27%**。
- W7900/gfx1100 路径也形成可复测 PR：1344×768、15 秒 dense 从 bring-up 的 **60,608 秒降至 4,624 秒**，但仍等待其他 ISA 回归。
- 依据：[v0.19.0](https://github.com/alexhegit/h3-hip.c/releases/tag/v0.19.0) · [v0.20.0](https://github.com/alexhegit/h3-hip.c/releases/tag/v0.20.0) · [W7900 PR #14](https://github.com/alexhegit/h3-hip.c/pull/14)

### 2. 扩展 H3 在 NVIDIA GB10 上的加速路径

- h3-spark.c 标记 **v0.2.4**，增加可选 FastH3、TAEH3、Pika 和 VSA；默认路径及既有 fox-fast 基线不变。
- GB10 的 832×480、5 秒任务中，VSA sparse-MMA 将 denoise 从约 **151 秒降至 34 秒**，端到端约 **58 秒**；同时保留各路径样例视频和已知 TAEH3 冷启动画质问题。
- 依据：[v0.2.4 Tag](https://github.com/alexhegit/h3-spark.c/releases/tag/v0.2.4) · [实现提交](https://github.com/alexhegit/h3-spark.c/commit/40ccaf573f)

### 3. EdenLive 在 MI300X 上完成从兼容性到流式解码的分阶段验证

- 为缺少 FlashAttention 4 CuTe 内核的 ROCm 环境提供 SDPA fallback，完成 5B 与 14B 双向生成验证；`torch.compile` 在 5B bidir 路径取得约 **1.27×** 加速。
- torchao FP8 W8A8 微基准最高达到 **1.64×**，但端到端反而约 **219 秒对 170 秒**，因此默认关闭并明确记录不采用结论。
- 新增时间因果 chunk 解码实验：720p/717 帧首个 chunk 解码约 **0.63 秒**、稳定阶段约 **1.19 秒/chunk**，帧数完整；同时确认当前 MI300X 路径仍无法达到 24 FPS。
- 依据：[edenlive-rocm](https://github.com/alexhegit/edenlive-rocm) · [流式解码提交](https://github.com/alexhegit/edenlive-rocm/commit/401b5ae8a081b2798b193b2ffe48cb2d0ad60e03)

### 4. 修复 UnrealRoboticsLab 的 Vulkan 深度回读崩溃

- 向上游提交 Vulkan 深度相机修复，将内部 render target 调整为受 UE 5.7 Vulkan 回读支持的 RGBA32F，同时保持外部单通道 float32 深度协议不变。
- 已通过 Linux NullRHI **269/269** 测试及 NVIDIA A30 Vulkan 实机 smoke test，但代价是内部深度 render target 显存和复制带宽增至四倍。
- 依据：[URLab-Sim/UnrealRoboticsLab PR #89](https://github.com/URLab-Sim/UnrealRoboticsLab/pull/89)

## rocPAI-Forge

### 1. vla-hip 连续优化三类模型，并发布至 v0.3.1

- 连续发布 [v0.2.2](https://github.com/rocPAI-Forge/vla-hip.c/releases/tag/v0.2.2) 至 [v0.3.1](https://github.com/rocPAI-Forge/vla-hip.c/releases/tag/v0.3.1)，将优化工作从通用小内核推进到各模型的关键瓶颈。
- **pi0.5 v0.2.5**：融合专家 GeGLU/RoPE epilogue并减少 kernel launch，BF16 从 **132.49 降至 130.01 ms**，INT8 从 **121.33 降至 117.26 ms**，52/52 输出逐位一致。
- **GR00T N1.7**：40/41-row packed GEMM 改用三个 row fragment，INT8 DiT 从 **58.34 降至 53.48 ms**；该改动保持全部输出逐位一致。
- **VLA-JEPA v0.3.0/v0.3.1**：fp16 WMMA ViT attention先将双视角 BF16 从 **50.71 降至 48.69 ms**，后续 LM 与 ViT GEMM 优化进一步降至 **47.50 ms**，INT8 DiT 为 **46.10 ms**。
- VLA-JEPA 数值路径已重跑四套 LIBERO、每套200回合：BF16/INT8 平均成功率约 **97.9%/98.3%**，均落在旧版本种子波动范围内；v0.3.1 相对 v0.3.0 再次做到 52/52 逐位一致。
- 依据：[v0.2.5](https://github.com/rocPAI-Forge/vla-hip.c/releases/tag/v0.2.5) · [v0.3.0](https://github.com/rocPAI-Forge/vla-hip.c/releases/tag/v0.3.0) · [v0.3.1](https://github.com/rocPAI-Forge/vla-hip.c/releases/tag/v0.3.1)
